# Safety

OEM automatic battery-fan control is the default. The Prius c/NHP10 fan control now has a narrow, sourced 1–6 allow-list with explicit user confirmation, ECU reads before/after each write, action logging, and serialized header routing. See docs/fuel-fan-fix.md for source evidence and the remaining physical-car validation limits. Smart cooling, other customizations and Diagnostic Maintenance Mode remain unavailable.

Any future write must be profile-matched, allow-listed, write-verified, explicitly confirmed, logged, serialized through the one command queue, read before change, and read back after change. The bounded NHP10 fan path uses runtime readback and does not promote profile verification status based on simulator results. Stationary/gear prerequisites must fail closed when data is absent. An emergency stop cancels pending writes. The NHP10 fan path stops repeating actuator commands on Auto, disconnect or any failed readback; screen navigation and backgrounding keep the active session running. It never substitutes fan level zero for OEM automatic control. A separate NHP10 release command is not established by the published source: the UI therefore reports stopping manual requests rather than claiming a verified ECU-auto transition, and explains that a vehicle power cycle may be needed. Process termination cannot be assumed to restore an ECU.

Never add commands affecting airbags, pretensioners, ABS, brake or steering calibration, immobilizer/keys, firmware, odometer, or emissions programming. Do not expose arbitrary CAN writes in production.

The bounded 1–6 battery-fan control permits level selection while moving, as explicitly requested by the user. Other configuration and diagnostic work should be performed while parked. Dashboard information is advisory, can be delayed or wrong because of adapter/vehicle faults, and is not a replacement for qualified service.
